# Sicherheit dieses Projekts

Unterstützter Stand: 0.1.x als Pilotprojekt, ohne Garantie der Schadsoftware-Erkennung.
Bei Fehlern in Prüfcode oder Datenschutz die betroffene Version vor weiteren
Prüfläufen aussetzen. Auswirkungen, sichere Reproduktion mit künstlichen Daten
und Fix in einem kontrollierten Review dokumentieren.

Keine echten Secrets, Malware-Samples, Geräteprotokolle, medizinischen oder
persönlichen Daten in Issues, Pull Requests oder Actions-Ausgaben einstellen.
In diesem privaten Repository ausschließlich abstrahierte technische Befunde
besprechen. Bei realen Vorfällen gilt `docs/incident-response.md`.

Keine fremden Befehle aus Meldungen ausführen. Änderungen am Prüfcode lokal
prüfen, insbesondere Schreibzugriffe, Netzwerkanfragen und Datenexporte.
